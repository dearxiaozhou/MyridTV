RH-API 工作流布局：目标 vs 旧 vs 新（用源码真实 DOM 渲染）

本页直接把 renderRunningHubParams() 输出的真实 innerHTML 串 + 真实 smart-canvas.css 渲染出来。A 列是图片模式 api-single-row（你要的目标），B/C/D 是 RH 工作流模式在「默认 / 加 rh-single-row / 加 rh-single-row+字段」下的真实效果。没用任何手写 mock。

目标 图片模式 api-single-row

目标观感：参数 chip 单行、透明无框、运行按钮圆形。

旧 RH 工作流 · 默认布局

2 素材 · 1 提示词

现状：3 个控件是块级 div，各占一行 + 带边框 + 有图标和 caret → 这就是你截图里「大块带框、分两行」。

新 RH 工作流 · rh-single-row

2 素材 · 1 提示词

新效果：3 个 chip + 素材提示词摘要同一行，透明无框、图标/caret 隐藏、chip 间竖线分隔、运行按钮圆形。已对齐目标。

新+字段 RH 工作流 · 有参数字段时

2 素材 · 1 提示词
种子

字段（种子/重绘幅度）保留边框、自动换行到第二行 —— 刻意保留可编辑感，不与 3 个 chip 抢单行空间。

诚实说明：本页用真实 CSS 渲染了真实 DOM 串，所以「新 vs 旧」的差异是可信的；但它仍是静态 HTML 快照，不等同于在软件里点开 RH 工作流节点时的实时渲染（实时还会有弹层、hover、i18n 文案等）。 最终以软件内 Ctrl+Shift+R 强刷后实际效果为准。若 C 列与你的截图 #1 目标仍有出入，大概率是：① 你截图里某些 chip 文案/数量不同；② 你期望「严格不换行(nowrap)」而非「放得下才单行(wrap)」。这两点告诉我即可调。
